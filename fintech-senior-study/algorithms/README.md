# 🧠 핀테크 시니어 코딩테스트 & 알고리즘 마스터 가이드

> **핵심 철학**: 수백 문제를 눈으로 대충 넘기는 학습은 실전 면접이나 라이브 코딩에서 반드시 무너집니다.  
> 한 문제를 풀더라도 **"요구사항 분석 ➔ $O(N^2)$ 브루트포스 ➔ 병목 식별 ➔ 자료구조 도출 ➔ $O(N)$ 최적화 ➔ Clean Modern Java 리팩터링 ➔ 3회 백지 타이핑 ➔ 면접 스크립트 완결"**의 7단계를 체화합니다.

---

## 🎯 1. 6년 차 백엔드 엔지니어의 코딩테스트 접근법 (7단계 프레임워크)

```text
[1. 완전 탐색 구상]  ➔  [2. 병목 구간 탐색]  ➔  [3. 최적 자료구조 선택]
 (Brute Force O(N²))     (매번 반복 탐색이 원인)      (조회 O(1) HashMap/HashSet)
                                                           │
                                                           ▼
[7. 면접 스크립트]   ◀─  [6. 3회 백지 타이핑]  ◀─  [5. Clean Modern Java] ◀─ [4. 최적화 구현]
 (복잡도/트레이드오프)      (손으로 체득하는 훈련)       (불변 Record, Capacity 최적화) (단일 순회 O(N))
```

1. **완전 탐색 (Brute Force)**:
   * 가장 직관적인 생각으로 문제를 해결하고, 시간/공간 복잡도를 명확히 계산합니다.
2. **병목 식별 (Find the Bottleneck)**:
   * "왜 느린가?"를 규명합니다. (예: 2중 for문으로 인해 $N$개의 요소마다 또다시 $N$번을 선형 탐색함)
3. **자료구조 선택 (Data Structure Selection)**:
   * 과거에 방문한 원소를 다시 찾을 때 $O(N)$이 걸리는 선형 탐색을 $O(1)$의 상수 시간에 끝내기 위해 해시 테이블(`HashMap` 또는 `HashSet`)을 도입합니다.
4. **최적화 구현 (Optimized Solution)**:
   * 단 한 번의 순회(1-Pass, $O(N)$)로 문제를 해결합니다.
5. **Clean & Modern Java 적용**:
   * `nums`, `diff`, `map` 같은 모호한 이름을 `numbers`, `requiredNumber`, `indexByNumber`처럼 도메인을 드러내는 명확한 이름으로 개선.
   * `int[]` 대신 의미가 분명한 불변 `record IndexPair(int firstIndex, int secondIndex)` 객체화.
   * `Objects.requireNonNull` 방어적 검증과 Map의 리사이징(Rehashing) 오버헤드를 막는 초기 용량(`initialCapacity`) 최적화.
6. **3회 백지 타이핑 훈련**:
   * 눈으로 보지 않고 손가락과 뇌의 시냅스에 알고리즘 뼈대를 영구 각인.
7. **면접 스크립트 작성**:
   * "이 문제를 어떻게 접근하셨나요?" 질문에 시간/공간 복잡도와 트레이드오프를 30초 내로 유창하게 설명.

## ⌨️ 2. 손으로 체득하는 "3회 직접 타이핑 훈련법"

> **"코딩테스트는 머리로 푸는 것이 아니라 손가락 끝의 감각으로 완성된다."**

복붙이나 단순 눈독은 `Map` 선언 방식, 널 체크, 인덱스 계산 순서 등의 미세한 실수 포인트를 가려버립니다.

* **1회차 (이해와 타이핑)**:
  * 해설과 소스 코드를 한 줄씩 음미하며 그대로 직접 타이핑합니다.
* **2회차 (기억 재구성)**:
  * 작성한 코드를 덮고, 백지 파일([`TwoSumPractice.java`](../src/com/ho/study/algorithm/day01/TwoSumPractice.java))에서 처음부터 끝까지 스스로 작성합니다.
* **3회차 (시간 간격 복습)**:
  * 15~20분 휴식 후, IDE 힌트 없이 다시 한 번 작성하여 컴파일 및 테스트 통과를 확인합니다.
* **익일 아침 (최종 점검)**:
  * 다음 날 아침 첫 일과로 아무것도 보지 않고 타이핑하여 1분 안에 통과할 수 있는지 확인합니다.

## 🗝️ 3. 핵심 자료구조 선택의 본질

자료구조를 선택할 때는 항상 **"내가 저장하려는 데이터의 성격"**을 자문해야 합니다.

| 상황 / 요구사항 | 선택 자료구조 | 시간복잡도 | 금융/분산 시스템 실무 매핑 |
| :--- | :---: | :---: | :--- |
| **"값과 연결된 다른 정보(인덱스, 카운트 등)가 필요하다"** | **`HashMap<K, V>`** | 조회 평균 $O(1)$ | • `userId ➔ UserSession`<br/>• `accountNumber ➔ Account`<br/>• Two Sum: `number ➔ index` |
| **"오직 존재 여부(중복 방지, 방문 여부)만 필요하다"** | **`HashSet<E>`** | 추가/조회 평균 $O(1)$ | • **결제 멱등성 (Idempotency)**: 이미 처리된 `transactionId`인가?<br/>• Kafka 중복 컨슘 방지: 처리된 `eventId`<br/>• 첫 번째 중복 문자 탐색 |
